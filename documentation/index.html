    Template documentation · Version 1.0

    Make it your own.

    Setup, customization, integrations, and the small details that make this template easy to work with.

    Start here

    Open index.html directly, or run npm start from the project folder and visit http://127.0.0.1:4173 . The public website has no build-time or remote runtime dependency. Bootstrap, icons, fonts, scripts, and photographs are stored locally.

    For development, run npm install once. npm run build regenerates the HTML from scripts/build.cjs . The shipped HTML is editable directly; if using the generator, make content changes there to avoid overwriting edits.

    The pages

    Two ten-section homepages, shop, product details, brands, grooming, journal, about, contact, 404, and coming soon. Care tips expand directly inside journal cards. No dashboard is included.

    Colors, spacing, and type

    Edit the CSS variables at the top of assets/css/style.css . The shared container is 1240px wide with equal responsive margins. An 8px spacing rhythm, reusable headings, buttons, and grid classes keep pages consistent.

    Dark-theme overrides live in assets/css/dark-mode.css . Theme preference follows the system until manually changed and persists in local storage. The RTL button persists layout direction; logical CSS handles most alignment, with overrides in assets/css/rtl.css .

    DM Sans is hosted locally under the SIL Open Font License in assets/fonts/OFL.txt . Editorial headings use the system Georgia serif font.

    Catalog and images

    The refined presentation layer is in assets/css/premium.css : 17px paragraphs, 16px action labels, framed category and product cards, inset journal panels, circular testimonial portraits, and consistent hover and focus states. scripts/premium-components.cjs supplies the original crest and different closing compositions for each page. Portrait origins are recorded in testimonial-assets.json . Run node tests/readability.cjs with the preview server running to check text sizes.

    Illustrative products are defined in scripts/build.cjs . Shop controls filter visible items by pet, type, brand, price, and name, with sorting and reset. Restwell opens the detailed product page. The other product cards have View buttons that open the shop; their image and title links open a prefilled special-order enquiry. Original brand emblems are defined in scripts/brand-emblems.cjs .

    All content images are WebP. Each photograph has one independent use across the site. The product gallery changes the main display when a thumbnail is selected; this is one gallery, rather than a second independent use.

    Image usage map lists page references. Stock source URLs and generated asset manifest identify origins. Original AI photography and product shots were made with the built-in image-generation tool; prompts are summarized in image-prompts.md .

    Connect the forms

    The template validates inputs and shows clearly labeled demo success messages. It does not transmit or persist personal information, process orders, or book appointments.

    1. Choose your form service and configure its endpoint in the relevant form.
    2. Update the submit handler in assets/js/main.js to send data only after validation, or use a standard POST form supported by the provider.
    3. Add loading, failure, and genuine delivery success states. Enable appropriate server-side validation and abuse protection.
    4. Replace demo notices and policy placeholders with accurate business information.

    Formspree or Netlify Forms can handle enquiries; Mailchimp or ConvertKit can handle newsletters. Provider setup is required. The optional image field checks type and a 5 MB limit; no image is uploaded by the demo.

    Before publishing

    • Replace fictional brands, store address, phone, email, prices, specifications, and customer stories.
    • Replace https://example.com in canonical tags, Open Graph metadata, JSON-LD, sitemap, and robots.txt.
    • Configure genuine social profile links, your map embed, privacy policy, terms, returns, and service conditions.
    • Update the coming-soon launch timestamp in its data-countdown attribute.
    • Configure your host’s custom 404 document to pages/404.html . The development server demonstrates a 404 response.
    • Verify the current license requirements of stock photography and vendor dependencies for your distribution. For marketplace resale, replace stock photos with assets you have confirmed redistribution rights for.

    Testing and review

    Run the local server, then npm test . The audit checks all public pages at 320, 360, 375, 390, 414, 420, 480, 640, 768, 820, 1024, 1280, 1440, and 1920px in light and dark themes. RTL is checked at 320, 820, and 1440px. It also checks local links, H1 counts, metadata, broken images, repeated content-image references, browser errors, and meaningful interaction flows.

    The test uses Microsoft Edge on Windows by default. Set BROWSER_PATH to a Chromium-compatible browser executable for another environment. Reports and page screenshots are saved under tests/ .

    Layout audits are not a guarantee of WCAG compliance or a PageSpeed score. Recheck your final content, integrations, and hosting with accessibility and performance tools.
